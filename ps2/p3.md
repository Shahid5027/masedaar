Continue developing the existing EDUCORE AI PS2 project.

Phases 1 and 2 are already implemented. Inspect the existing backend, frontend, database schema, assessment workflow, submission upload, PDF/TXT extraction and tests before making changes.

Do not rebuild existing functionality. Do not modify PS1 or PS3. Keep all PS2 work inside the existing ps2 directory.

## 1. Semantic matching engine

Implement actual sentence embeddings using Sentence Transformers.

Use a suitable lightweight pretrained model, such as all-MiniLM-L6-v2, subject to dependency compatibility.

Implement:
- Reference answer embedding.
- Student answer sentence/chunk embeddings.
- Cosine similarity.
- Concept-level semantic matching.
- Similarity thresholds configurable through settings.
- Safe model loading and error handling.

Do not use hardcoded similarity scores or simulated AI results.

## 2. Text preprocessing

Improve the existing text preprocessing service.

Requirements:
- Preserve technical terms.
- Preserve numbers and units.
- Preserve equations and symbols where possible.
- Preserve negations.
- Split long answers into meaningful sentences/chunks.
- Normalize whitespace without destroying meaning.

## 3. Rubric-based grading

Implement criterion-level evaluation.

For each rubric criterion:
- Identify expected concepts.
- Identify matching evidence in the student's answer.
- Identify missing concepts.
- Identify incorrect or contradictory claims where supported by evidence.
- Calculate evidence coverage.
- Estimate correctness.
- Allocate partial credit.

Use the initial transparent heuristic:

Criterion score = Criterion maximum marks × Evidence coverage × Correctness factor.

Both coverage and correctness must be between 0 and 1.

Clamp every criterion score between zero and its maximum marks.

Ensure total marks never exceed the question maximum.

Semantic similarity alone must never determine marks.

## 4. Explainable evaluation results

Save and return:
- Suggested marks.
- Maximum marks.
- Criterion-level marks.
- Expected concepts.
- Identified concepts.
- Supporting student answer excerpts.
- Missing concepts.
- Incorrect concepts where established.
- Confidence or review warnings.
- Grading method.
- Evaluation timestamp.

Do not invent evidence or claim a concept is missing without checking the student's answer.

## 5. Feedback generation

Generate concise, constructive, concept-specific feedback.

Feedback should include:
- What the student explained correctly.
- Which important concepts are missing.
- Which explanations need correction.
- How the student can improve.
- Relevant topics to revise.

Use structured grading findings as the source of feedback.

If an LLM is unavailable, use a deterministic template fallback.

Never allow generated feedback to invent facts.

## 6. Database integration

Use the existing evaluations table and database relationships.

Preserve all existing submission and assessment data.

Store criterion results, identified strengths, missing concepts, feedback, suggested marks, grading method and evaluation status.

Do not overwrite AI suggested marks when faculty moderation is implemented later.
