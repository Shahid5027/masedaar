# PHASE 2 – ASSESSMENT MANAGEMENT AND DOCUMENT PROCESSING

Continue developing the existing EDUCORE AI PS2 project.

First inspect the files created in Phase 1. Reuse the existing architecture. Do not rebuild the project or modify PS1 and PS3.

## 1. Faculty assessment management

Build a fully functional faculty assessment dashboard.

Allow faculty to:

- Create an assessment.
- Enter assessment title.
- Select subject.
- Add questions.
- Enter maximum marks.
- Enter reference answers.
- Add multiple rubric criteria.
- Assign maximum marks to each criterion.
- Add required and optional concepts.
- Edit and delete questions.
- Save assessments in Supabase.

Validate that the sum of rubric criterion marks equals the question maximum marks.

## 2. Submission management

Create a functional student submission upload screen.

Support:

- PDF files.
- TXT files.

Capture:

- Student ID.
- Student name (optional).
- Assessment ID.
- Uploaded file.
- Upload timestamp.
- File type.

Validate file extensions, file size and upload errors.

Store uploaded documents in Supabase Storage.

## 3. PDF and TXT extraction

Use PyMuPDF for digital PDF text extraction.

TXT files should be read directly.

Implement:

- PDF text extraction.
- TXT text extraction.
- Text normalization.
- Paragraph and line-break preservation.
- Extraction status.
- Empty document detection.
- Unreadable document handling.

Create an OCR service interface using PaddleOCR or Tesseract for future scanned-document support, but prioritize PDF/TXT functionality.

## 4. Extraction preview

After uploading a submission, display:

- Original filename.
- Student ID.
- File type.
- Extraction status.
- Extracted answer text.
- Extraction warnings.
- Editable extracted text for faculty correction.

Never grade an empty or unreadable submission.

Save the corrected extracted text separately or preserve its edit history.

## 5. Database integration

Connect all functionality to Supabase PostgreSQL.

Use the existing tables and schema from Phase 1.

Save assessments, questions, rubrics and submissions.

Use appropriate relationships and foreign keys.

## 6. API endpoints

Implement:

POST /api/ps2/assessments

GET /api/ps2/assessments

GET /api/ps2/assessments/{assessment_id}

POST /api/ps2/assessments/{assessment_id}/questions

POST /api/ps2/assessments/{assessment_id}/submissions

GET /api/ps2/submissions/{submission_id}

## 7. UI expectations

Create professional working interfaces for:

- Assessment list.
- Create assessment.
- Question and rubric editor.
- Submission upload.
- Extraction preview.

Use loading, success, empty and error states.

Do not use placeholder buttons.

## 8. Testing

Test:

- Assessment creation.
- Question creation.
- Rubric validation.
- PDF upload.
- TXT upload.
- PDF extraction.
- Empty PDF handling.
- Unsupported file rejection.
- Database persistence.

## Completion requirements

At the end, provide:

- Completed features.
- Working API endpoints.
- Database changes.
- Test results.
- Remaining issues.

The application must support this complete flow:

Create assessment → Add rubric → Upload answer → Extract text → Preview answer.

Do not implement the advanced AI grading engine yet. That belongs to Phase 3.
