# 3. INTERVENTION API ENDPOINTS

Implement the following endpoints under `/api/ps3`.

Use the existing API response envelope:

`{ status, message, data, errors, meta }`

Suggested endpoints:

### List interventions

GET `/api/ps3/interventions`

Support:
- Pagination.
- Student ID filter.
- Status filter.
- Priority filter.
- Assigned counsellor filter.
- Search where appropriate.
- Sorting by creation date and follow-up date.

### Get intervention details

GET `/api/ps3/interventions/{intervention_id}`

Return:
- Intervention details.
- Student reference.
- Related prediction information.
- Assignment information.
- Current status.
- Follow-up information.
- History, if implemented.

### Create intervention

POST `/api/ps3/interventions`

Validate:
- Student exists.
- Related prediction exists if supplied.
- Required fields are valid.
- Priority and status values are supported.

### Update intervention

PATCH `/api/ps3/interventions/{intervention_id}`

Support safe updates to:
- Assigned counsellor.
- Status.
- Priority.
- Follow-up date.
- Description.
- Notes.

### Intervention history

GET `/api/ps3/interventions/{intervention_id}/history`

Return a chronological record of meaningful intervention changes.

### Student interventions

GET `/api/ps3/students/{student_id}/interventions`

Return all interventions associated with a student.

### Endpoint design requirements

- Use proper HTTP status codes.
- Validate all request data.
- Handle missing students and interventions.
- Prevent invalid state transitions where appropriate.
- Avoid duplicate or accidental records.
- Use database transactions.
- Preserve the standard response envelope.
- Document all endpoints.
- Add tests for every endpoint.

If the existing project uses a different naming convention, preserve it consistently.

# 4. COUNSELLOR WORKFLOW

Build a complete workflow rather than simply storing recommendations.

### Suggested workflow

1. The ML model identifies a student with elevated dropout risk.
2. The system generates explainable risk indicators and recommendations.
3. A counsellor opens the student's profile.
4. The counsellor reviews the AI recommendation.
5. The counsellor decides whether intervention is appropriate.
6. The counsellor creates an intervention.
7. The counsellor assigns responsibility.
8. The intervention progresses through its status.
9. Follow-up is scheduled.
10. The counsellor records the outcome.
11. The intervention is completed or reopened.

### Human decision-making

AI recommendations must remain advisory.

Never automatically assign, contact, penalize or otherwise take action against students based solely on model predictions.

A counsellor must review and approve interventions.

Do not assume that a high-risk prediction means a student will drop out.
